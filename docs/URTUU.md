# «Өртөө» — платформ хоорондын үйлчилгээний суваг

Их Монгол Улсын өртөө шуудан: захиаг өртөөнөөс өртөөнд дамжуулж, хүрсэн
эсэхийг нь буцааж мэдэгддэг байсан. Nexus дээр суурилсан платформууд дээд/доод
холбоосоор хэлхэгдэж, урьдчилан бүртгэгдсэн **хүсэлтийн кодоор** даалгавар
доошоо урсаж, биелэлт нь дээшээ буцна.

[Дизайны санал](URTUU_PROPOSAL.md) ·
[Ring стандарт](RING_STANDARD.md) ·
[Цөмийн баримтууд](https://github.com/gerege-systems/open-gerege-nexus/tree/main/docs)

> **2026-08-27.** Энэ баримт цөмийн репод байсан бөгөөд Өртөөгийн хамт энд
> ирэв. Гурван давхаргын аль нь ч цөмд үлдсэнгүй — доорх §1-ийг үз.

> **Нэр томьёо.** Дэлгэц дээр албан хэрэг хөтлөлтийн нэршлийг барина:
> **дээд шатны байгууллага** (кодод `parent`) ба **харьяа байгууллага**
> (кодод `child`). Энэ баримтад чиглэлийг товчоор "дээд тал / доод тал" гэж
> бичсэн газар байгаа нь тэдгээртэй ижил утгатай — код дахь утга нь
> `parent`/`child` хэвээр, тэр нь утсан дээр явдаг нэр.

## 1. Гурван давхарга

| Давхарга | Байршил | Юу хийдэг |
| --- | --- | --- |
| **Гэрээ** | `domain/urtuu/wire` | Дугтуй, Ed25519 гарын үсэг, даалгаврын статусын машин, хүсэлтийн кодын төрөл, ба самбар–суваг хоёрын хоорондох `Link`/`PeerDirectory` |
| **Тээвэр** | `modules/urtuu/channel` | Холбоос, гарах/ирэх дараалал, хүргэлтийн retry, идемпотент хүлээн авалт, pull/push цэгүүд, ring импортлогч |
| **Апп «Өртөө»** | `modules/urtuu` (`io.gerege.nexus.urtuu`) | Даалгаврын амьдралын мөчлөг, дэлгэцүүд, самбар, тайлангууд |

**Тээвэр яагаад цөмөөс гарав.** 2026-08-15-нд тээврийг платформд үлдээсэн
үндэслэл нь: админы байгуулсан холбоос дээгүүр яваа ажил тухайн аппыг устгасан
ч алга болох ёсгүй, мөн ирээдүйд өөр модуль сувгийг ашиглаж магадгүй. Эхнийх нь
үнэн хэвээр, хоёр дахь нь гурван сарын турш болсонгүй: `nexus.Link`,
`nexus.PeerDirectory` хоёрын **цорын ганц** дуудагч нь энэ апп байв. Ганц
хэрэглэгчтэй рельс бол рельс биш тул суваг 2026-08-27-нд аппынхаа хамт ирэв
(цөмийн миграц `00087`, аппын `00002`).

**Юу өөрчлөгдсөн бэ.** Апп суулгаагүй суулгац одоо дугтуй хүлээн авахаа болино.
Өмнө нь дугтуй ирж, шалгагдаж, хадгалагдаж, апп суулгагдмагц уншигдаж байсан.
Одоо суваг нь аппын дотор тул суулгаагүй бол `/.well-known/urtuu.json`,
солилцооны хоёр цэг байхгүй — нөгөө тал 404 авна. Аль хэдийн байгаа холбоос
дээрх дараалал устахгүй: хүснэгтүүд нь мөн энэ аппынх бөгөөд апп дахин
суулгагдахад дараалал тэндээ хэвээр байна.

## 2. Хоёр зарчим, бүх зүйл эднээс гарна

### 2.1 Доод тал л холбогдоно

Дээд платформ доод руу **хэзээ ч** гарахгүй. Доод суулгац галт ханын цаана,
хувийн сүлжээнд, эсвэл түр унтраатай байж болно — дээд талаас эхэлдэг холбоос нь
зөвхөн нэг талаас ажилладаг холбоос болно.

Тиймээс доод тал өөрөө дээд рүүгээ:

- `GET /api/v1/urtuu/exchange/pull` — хүлээгдэж буй дугтуйг татна (25 секунд
  хүртэл нээлттэй барина; `?wait=0` бол шууд хариулна),
- `POST /api/v1/urtuu/exchange/push` — өөрийн шинэчлэлт болон **баталгаа**-г
  илгээнэ.

Каталог sync яг ижил шалтгаанаар pull сонгосон.

**Nginx-ийн зам.** Солилцоо нь `/api/v1/urtuu/…` дор явдаг тул `/api/` дамжуулалт
хангалттай (25 секундын long-poll нь 90 секундын `proxy_read_timeout`-д багтана).
Харин `/.well-known/urtuu.json` нь домэйны үндэс дээр сууж, тэнд `/` нь
frontend рүү явдаг тул ТУСДАА route хэрэгтэй — `deploy/nginx/snippets/nexus-oauth.conf`-д
байгаа. Байхгүй бол доод тал дээдийн түлхүүрийн оронд Next.js-ийн HTML 404 авч,
handshake нь ойлгомжгүй алдаагаар унана.

### 2.2 Token нь "хэн ярьж байна", гарын үсэг нь "хэн бичсэн"

Хоёр өөр асуулт, дугтуй бүр дээр хоёулаа асуугдана. Хулгайлагдсан token нь
харилцах эрх өгнө, юу ч зохиох эрх өгөхгүй; хуурамч дугтуй нь холбоос
байгуулахад солилцсон нийтийн түлхүүрийг давж чадахгүй.

## 3. Тохиргоо

| Хувьсагч | Хаана | Юу |
| --- | --- | --- |
| `URTUU_SIGNING_KEY` | Суулгац бүр (`deploy/docker-compose.yml`) | Энэ суулгацын Ed25519 түлхүүр, base64. 32 байт seed эсвэл 64 байт private key хоёуланг хүлээж авна. **Тавигдаагүй бол Өртөө унтраалттай** — платформ хэвийн асна, зөвхөн сувгийн үйлчилгээ ажиллахгүй |
| `URTUU_ALLOW_INSECURE_PEERS` | Суулгац бүр | `1` бол `http://` хаягтай холбоос зөвшөөрнө. Анхдагчаар унтраалттай: холбоосын token нь `Authorization` толгойгоор явдаг тул http дээр байгуулсан холбоос түүнийг замд байгаа бүх хүнд өгнө. Төрийн хаалттай сүлжээн дэх суулгацууд л үүнийг зориудаар асаана |
| `RING_BASE_URL` | Кодын эх сурвалж | ring.dgov.mn-ий хаяг. `mock` гэж тавибал хөгжүүлэлтийн жишиг кодууд ирнэ (нэр дээрээ «жишиг» гэж бичигдсэн). Тавигдаагүй бол импорт унтраалттай, локал кодууд ажиллана |
| `RING_API_KEY` | Кодын эх сурвалж | Ring-ийн Bearer түлхүүр. `RING_BASE_URL` бодит хаягтай бол заавал |
| `RING_PUBLIC_KEY` | Кодын эх сурвалж | Бүртгэлийн гарын үсэг шалгах Ed25519 нийтийн түлхүүр, base64. **Заавал** — шалгагдаагүй бүртгэл нь улсын бүх суулгац дээрх кодын утга, хугацааны нормыг өөрчлөх эрхтэй баримт |
| `PLATFORM_TIMEZONE` | Платформ даяар | Календарийн цагийн бүс. Анхдагч `Asia/Ulaanbaatar`. Бүртгэлийн дугаарын он, хугацааны заагийг энэ шийднэ — public contract-ыг [`pkg/nexus/clock.go`](https://github.com/gerege-systems/open-gerege-nexus/blob/main/backend/pkg/nexus/clock.go)-оос үз |

Түлхүүр үүсгэх:

```bash
openssl rand -base64 32
```

**Production дээр хаана тавих вэ.** `deploy/docker-compose.yml` нь хувьсагчдыг
нэрээр нь тус бүрд дамжуулдаг тул серверийн `/opt/open-gerege-nexus/.env`-д
бичээд л болохгүй — тухайн нэр compose дотор мөн байх ёстой. Дээрх бүх хувьсагч
`backend` үйлчилгээнд бүртгэгдсэн. Утгыг нь `/opt/client-nexus/.env`-д тавьж,
`docker compose up -d backend` (эсвэл дараагийн deploy) хийхэд хүчин төгөлдөр
болно. Цөмийн `docker-compose.prod.yml`-д эдгээр хувьсагч **байхгүй** болсныг
анхаар: цөмийн суулгац Өртөө ажиллуулдаггүй.

**Түлхүүрээ бүү сольж бай.** Түлхүүр солигдвол суулгацын ID өөрчлөгдөж, одоо
байгаа холбоос бүрийн token хүчингүй болж, нөгөө талын хадгалсан нийтийн
түлхүүр буруу болно. Холбоос бүрийн мөрөнд `installation_id` бичигдэж байдаг
тул тэдгээр нь **чимээгүй унтрахгүй** — аль нь хуучин түлхүүрээр байгуулагдсаныг
нэрлэж чадна — гэхдээ дахин байгуулах хэрэгтэй болно.

## 4. Холбоос байгуулах (handshake)

Гурван алхам, хоёр талын зөвшөөрөл (`report_grants`-ийн урсгал):

### Алхам 1 — Дээд тал урина

Тохиргоо → Өртөө → **Доод платформ урих**. Нэг удаагийн код гарч ирнэ:

```
POST /api/v1/urtuu/peers/invite   { "name": "Ховд аймаг" }
→ { "id": "...", "invite_code": "K7QM-3F9X-...", "expires_in_hours": 24 }
```

Код нь **24 цаг**, **нэг л удаа**, **дахин харагдахгүй**. Хадгалагддаггүй —
SHA-256 нь л хадгалагдана. Алдвал холбоосыг цуцлаад дахин урина.

### Алхам 2 — Доод тал буулгана

Доод платформын админ Тохиргоо → Өртөө → **Дээд платформд холбогдох**: дээдийн
хаяг + код.

```
POST /api/v1/urtuu/peers   { "invite_code": "...", "base_url": "https://yaam.gov.mn", "name": "Боловсролын яам" }
```

Энэ үед доод тал:

1. дээдийн `/.well-known/urtuu.json`-оос нийтийн түлхүүр, суулгацын ID-г татна,
2. өөр дээрээ холбоосын мөр үүсгэнэ,
3. дээдийн `/api/v1/urtuu/peers/redeem` рүү өөрийн нийтийн түлхүүр болон
   тухайн холбоосын token-оо илгээнэ.

Token нь **хадгалагддаггүй, гаргаж авдаг**: `HMAC(signing key, "urtuu-peer-token:"+peer_id)`.
Тиймээс доод талд ил нууц үлдэхгүй, дээд тал зөвхөн SHA-256-г нь хадгална.

### Алхам 3 — Дээд тал баталгаажуулна

Тохиргоо → Өртөө дээр хүлээгдэж буй холбоос гарч ирнэ → **Баталгаажуулах**.

```
POST /api/v1/urtuu/peers/{id}/confirm
```

Үүнээс өмнө pull/push нь **403** буцаана (холбоос байгаа, баталгаажаагүй).
Цуцлагдсан эсвэл байхгүй холбоос нь **401** буцаана — цуцлагдсан тал нь өөрийгөө
"хэзээ ч байгаагүй"-ээс ялгаж чадах ёсгүй.

### Цуцлах

```
POST /api/v1/urtuu/peers/{id}/revoke
```

Аль ч тал хэзээ ч цуцалж болно. **DELETE байхгүй**: "бидэнтэй хэн холбоотой
байсан бэ" гэдэг нь хожим асуугддаг асуулт.

## 5. Хүсэлтийн кодууд

Даалгавар **чөлөөт текстээр үүсэхгүй**. Код сонгоно, код нь юу бөглөхийг (JSON
Schema) болон хэдий хугацаанд хийхийг (SLA) өөрөө хэлнэ.

| Эх сурвалж | Хаанаас | Дүрэм |
| --- | --- | --- |
| `ring` | ring.dgov.mn-ээс импортлогдсон | Угтваргүй нэрийн орон зай (`Д-101`) тэднийх |
| `link` | Дээд тал холбоос дээр зарласан | Доод тал засварлаж чадахгүй; `active` тугийг л өөрөө шийднэ |
| `local` | Энд зохиосон | Заавал `local.` угтвартай — схемийн CHECK шаардана |

**Холбоос бүрд тусдаа.** Дээд тал өөрийн багцаасаа тухайн холбоос дээр аль
кодыг нээхээ шийднэ (Тохиргоо → Өртөө → холбоосын **Кодуудыг нээх**). Зарлал нь
бүтэн агшны зураг: хасагдсан код доод талаас автоматаар алга болно. Хоосон
жагсаалт нь бодит зарлал — тэгэж л нээсэн кодоо хаадаг.

Нэр давхцвал (доод тал өөрөө `local.x` зохиосон, дээд тал бас `local.x`
зарласан) **өөрийн тодорхойлолт ялна**.

### Ring импортлогч

Формат нь **бидний тогтоосон стандарт**: [`RING_STANDARD.md`](RING_STANDARD.md).
Тэднийг хүлээхгүй — гарын үсэгтэй баримт, ETag, нийтийн түлхүүрээр шалгах
хэлбэрийг санал болгож өгнө. Гарын үсгийн вход нь каталог болон Өртөөгийн
дугтуйтай яг ижил: `generated_at + '\n' + түүхий байт`. Нэг дүрэм гурван газар.

Хэрэгжилт: [`modules/urtuu/channel/ring.go`](../modules/urtuu/channel/ring.go).

- **Гарын үсэггүй бүртгэл хэзээ ч хүлээн авагдахгүй.** `RING_PUBLIC_KEY`
  тавигдаагүй бол импорт огт байхгүй.
- **Диск кэш байхгүй, зориудаар.** Импортлогдсон кодууд өгөгдлийн санд сууна —
  тэр нь өөрөө кэш. Ring унасан нь хуучирсан үгсийн сан гэсэн үг, ажил
  зогсохгүй.
- **Хуваарьт синк байхгүй, зориудаар.** Код нь хугацааны нормтой ирдэг, норм
  нь ажилтны хэмжигдэх зүйлийг өөрчилдөг. Улсын шинэ кодыг авах эсэх нь
  байгууллагын шийдвэр байх ёстой, шөнө дунд болох гэнэтийн зүйл биш.
- **Нэг муу бичлэг бүх импортыг унагаахгүй.** Кодгүй, монгол нэргүй, эсвэл
  `local.` орон зайг булаасан бичлэг нь өөрөө хаягдана.

### Ring-гүйгээр

`RING_BASE_URL` тохируулахгүй бол платформ бүрэн ажиллана: байгууллага
`local.` угтвартай кодоо зохиож, холбоос бүрд зарлана. Гинжний нэгдмэл байдал
хэвээр — зөвхөн улсын хэмжээнд биш, тухайн гинжний хэмжээнд. Ring нь эрсдэл
биш, нэмэлт.

## 6. Хоёр шугам

Өртөө хоёр төрлийн ажил зөөнө. Хоёр шугам гэдэг нь дэлгэцийн шүүлтүүр биш,
**хоёр өөр амлалт**:

| | **Үйлчилгээ** (`service`) | **Албан даалгавар** (`assignment`) |
| --- | --- | --- |
| Хэн эхлүүлэв | Иргэн, байгууллага — платформын **гадна** | Дээд байгууллага өөрөө |
| Хүсэгч | Заавал (нэр, регистр, холбоо барих) | Байхгүй |
| Юу заавал буцах вэ | **Хариу** — хүсэгчид өгөх хариулт | Биелэлтийн мэдэгдэл |
| Хаагдах болзол | Хариугүйгээр биелсэн болж **чадахгүй** | Эх тал үр дүнг хүлээн авна |

Хоёр дахь мөр нь схемд суусан:

```sql
CHECK (line <> 'service'
       OR target_peer_id IS NOT NULL      -- толь мөр: нөгөө талын хуулбар
       OR status NOT IN ('COMPLETED','CLOSED')
       OR answer <> '')
```

Go талын шалгалт нь хүнд ойлгомжтой өгүүлбэр буцаахын тулд байгаа; схемийн
шалгалт нь **мартагдахгүйн** тулд байгаа. Нэг handler дээрх шалгалтыг тойрч
болно, CHECK-ийг тойрч болохгүй.

**Шугам нь кодоос ирнэ, үүсгэгч хүнээс биш.** ring.dgov.mn-ээс импортлогдсон
код бол мөн чанараар нь төрийн үйлчилгээ; байгууллагын дотоод код бол
даалгавар. Хэрэв үүсгэгч сонгодог байсан бол нэг код хоёр өөр амлалттай
хоёр газар хэрэглэгдэх байв — амлалт нь ялгааны бүх агуулга.

**Задаргаа хийсэн үйлчилгээний хариу дээшээ цуглана.** Хэд хэдэн доод
байгууллагад буусан хүсэлт биелэхэд салбар бүрийн хариу эх мөр дээр
байгууллагын нэрээр нэрлэгдэн нийлнэ — "Тодорхойлолт олгов" гэсэн нэг хариу,
"Бүртгэл олдсонгүй" гэсэн нөгөө хариу хоёулаа тэр хүнийх.

**Хүсэгчид хариуг хэн хүргэх вэ.** Одоогийн хэрэгжилтэд хариу нь хүсэлт
хүлээн авсан суулгац дээр ирж, хүсэгчийн холбоо барих мэдээллийн хамт
харагдана. Иргэн рүү автоматаар и-мэйл/SMS илгээх нь энэ давхаргын ажил биш —
хүлээн авсан байгууллагын үйлчилгээний суваг (портал, ирүүлсэн хаяг) шийднэ.

## 7. Бүртгэлийн дугаар

UUID нь машинд төгс, хүнд хэрэггүй. Сумын ажилтан утсаар "манай 14 дэх
даалгавар" гэж хэлдэг, `f6215cd1-4d5f…` гэж хэлдэггүй. Тиймээс мөр бүр
**бүртгэлийн дугаартай**:

```
Д2026-00412     албан даалгавар
Ү2026-01875     үйлчилгээний хүсэлт
```

Эхний тэмдэгт нь **шугам** (Ү = үйлчилгээ, Д = даалгавар) — дугаарыг харангуут
хариу заавал буцах ёстой юу гэдгийг мэднэ. Дараалал нь тухайн суулгац, тухайн
шугам, тухайн он тус бүрд 1-ээс эхэлнэ.

### Шат бүр өөрийн дугаараар бүртгэж, эхийнхийг иш татна

```
БШУЯ      Д2026-00412
  └ Ховд    Д2026-0087   ← БШУЯ, Д2026-00412
     └ Буянт  Д2026-0014 ← Ховд, Д2026-0087
```

Ирсэн бичгийг өөрийн бүртгэлд дугаарлаж, илгээгчийн дугаарыг иш татдаг —
цаасан бичиг яг ингэж ажилладаг. Илгээсэн дугтуй бүр мөн дугаарлагдана
(гарах бичгийн бүртгэл), доод тал яг тэр дугаарыг иш татна.

Энэ нь `origin_chain`-тэй **давхардахгүй**: origin_chain нь машинд (мөчлөгийн
шалгалт, крипто ID-гаар), дугаар нь хүнд.

### Яагаад дугаарт платформын угтвар байхгүй вэ

`БШУЯ/Д2026-00412` гэсэн хувилбар авч үзэгдээд **гээгдсэн**. Холбоос бүрийн
мөр аль хэдийн `name` талбартай ("Ховд аймаг") бөгөөд түүнийг админ handshake
хийхдээ өөрөө өгдөг. Суулгац тусад нь богино код зарлаж эхэлбэл нэг зүйлийн
**хоёр дахь хүний нэр** үүсэх байв — хэн ч баталгаажуулдаггүй, хоорондоо зөрж
болох нэр. Тиймээс дугаарыг нөгөө талын нэртэй нь **хамт** харуулна:

```
Ховд аймаг · Д2026-0087
```

Цаасан дээр ч яг ийм: бичгийн дугаарыг гаргасан байгууллагынх нь нэртэй хамт
уншдаг, дугаар дангаараа хэзээ ч утгагүй.

### Дугаараар API-д хандахгүй

Дугаар нь хүний хэл: хэвлэх, хэлэх, хайхад. API-ийн танигч нь UUID хэвээр.
Дугаарлагч нь `urtuu_numbers` дээрх нэг мөр бөгөөд `UPDATE … RETURNING`-ийн
мөрийн түгжээгээр цуваачилна — advisory lock хэрэггүй. Гүйлгээ буцвал дугаар
буцаж өгөгдөнө: бүртгэлд нүх үлдээхгүй.

## 8. Даалгаврын амьдралын мөчлөг

```
ИРСЭН → ХҮЛЭЭН АВСАН → ХИЙГДЭЖ БАЙГАА → БИЕЛСЭН → (эх тал) ХААГДСАН
              ↘ БУЦААСАН (шалтгаантай)          ↗
              ↘ ЗАДАЛСАН → доод даалгаврууд → бүгд биелэхэд эх нь БИЕЛСЭН
хугацаа хэтэрвэл → ХОЦОРСОН (төлөв биш, туг: аль ч төлөв дээр асна)
```

Схемд хадгалагдах утга нь латин, том үсгээр (`RECEIVED`, `ACCEPTED`, …) —
платформын бусад бүх төлөв тэгж бичигддэг, CHECK constraint, Prometheus label,
тайлангийн шүүлт бүгд түүн дээр тулгуурладаг. Монгол нэр нь толь бичигт
(`frontend/lib/i18n/addons/urtuu.ts`) 7 хэлээрээ байна.

**Задаргаа (fan-out)** нь доод бүрд **тусдаа даалгавар** үүсгэж эхтэйгээ
`parent_task_id`-аар холбоно. Тиймээс "target_peers" гэсэн массив багана
байхгүй: массив байсан бол нэг ажил хоёр газар бичигдэж, хоёр нь зөрөх өдөр
гарцаагүй ирнэ.

**Хүсэгчийн мэдээлэл доошоо явна.** §2.4-ийн "өгөгдөл нүүдэггүй" дүрэм нь
БАЙГУУЛЛАГЫН дотоод өгөгдөл дээшээ урсахгүй гэсэн үг. Хүсэгчийн мэдээлэл нь
ажлын чиглэлийн дагуу доошоо явна — тодорхойлолт олгох алба хэнд олгохоо
мэдэхгүйгээр олгож чадахгүй — бөгөөд түүнээс өөр юу ч дагахгүй.

**Хэн хийж байгаа нь дээшээ явахгүй.** Дотоод хариуцагч оноох нь тухайн
байгууллагын хэрэг; дээд тал "хийгдэж байна" гэдгийг мэдэх бөгөөд түүнээс
илүүг биш (§2.4).

### Мөчлөгийн хамгаалалт

Даалгавар бүр `origin_chain` авч явна — дамжсан суулгац бүрийн ID. Ирсэн
даалгаврын гинжинд өөрийн ID байвал даалгавар **үүсэхгүй**, шалтгаантай
буцна. А→Б→А гэсэн холбоосын бүтэц өөрөө хууль ёсны (хоёр яам өөр өөр төрлийн
ажлаар бие биенийхээ дээд байж болно) — хамгаалагдах ёстой нь холбоос биш,
**даалгавар**.

## 9. Ажиллагааны runbook

### «Даалгавар доод тал руу очихгүй байна»

1. **Тохиргоо → Өртөө** → тухайн холбоосын мөрийг хар:
   - `Сүүлд холбогдсон` хоосон эсвэл хуучин уу? → доод тал холбогдохоо больсон;
   - `хүргэгдээгүй` тоо өсөж байна уу? → дараалал хуримтлагдаж байна;
   - улаан алдааны мөр байна уу? → нөгөө талын хариу шууд бичигдсэн байна.
2. Холбоос `Идэвхтэй` эсэхийг шалга. `Хүлээгдэж буй` бол дээд тал
   **баталгаажуулаагүй** байна.
3. Доод талын лог: `urtuu: exchange with a parent failed` мөрийг хай.
4. Хүргэлт **exponential backoff**-той (30 сек → 6 цаг). Нэг цагаас дээш
   хугацаанд хүрээгүй бол энэ нь оролдлогын хооронд байгаа гэсэн үг биш.

### «Дугтуй буцаагдаж байна» (`urtuu.rejected` audit)

Гарын үсэг шалгагдаагүй байна. Гурван шалтгаан:

- нөгөө тал `URTUU_SIGNING_KEY`-гээ сольсон → холбоосыг дахин байгуул;
- хадгалагдсан `peer_public_key` буруу → холбоосыг цуцлаад дахин байгуул;
- дунд нь агуулга өөрчлөгдсөн → энэ бол аюулгүй байдлын явдал, аудитыг үз.

### «Даалгавар шалтгаантай буцаж ирлээ»

Ирсэн `task.update`-ийн тайлбарыг унш:

- `origin chain` → мөчлөг. Тухайн салбар руу дахин илгээх утгагүй;
- `has no request code X` → доод талд тэр код байхгүй. Холбоос дээр кодоо
  нээгээгүй, эсвэл зарлал хараахан хүрээгүй байна;
- `is not in use` → доод тал тэр кодыг өөрөө унтраасан байна.

### «Цагийн зөрүү» анхааруулга

SLA-г **илгээгчийн** `created_at`-аар тооцно (§9), тиймээс платформ цагийг
чимээгүй засахгүй — зөрүүг холбоосын мөрөнд бичиж, харагдуулна. 5 минутаас дээш
зөрүү бол нөгөө талын NTP-г шалга.

### Хэмжигдэхүүнүүд

| Метрик | Утга |
| --- | --- |
| `urtuu_tasks_total{status}` | Шилжилт бүр, төлөвөөр |
| `urtuu_deliveries_total{result}` | `ok` — нөгөө тал баталсан; `failed` — солилцоо тасарсан |
| `urtuu_peer_last_seen_seconds{role}` | Хамгийн удаан дуугүй байгаа идэвхтэй холбоос, чиглэлээр |

**Тенантын label хаана ч байхгүй** (MONITORING.md). Байгууллагаар задлах нь
тайлангийн асуулт бөгөөд өгөгдлийн сангаас хариулагдана — тэнд мөр устгагдаж
чадна, Prometheus-ийн цуваа устдаггүй.

Оператор консолын нүүрэн дэх «Өртөө» гэрэл 2026-08-27-нд унтрав: цөм сувгийн
хүснэгтүүдийг мэдэхээ больсон тул тэр самбарыг үзүүлэх нь энэ бинарийн
ажиллуулдаггүй зүйлийн эрүүл мэндийг мэдээлж байгаа хэрэг болно. Операторын
уншилтын бодлого нь хүснэгтүүдийн хамт энд үлдэв (`00002`: зөвхөн
`urtuu_peers`, `urtuu_deliveries` — агуулга биш), тиймээс консолыг сэргээх
шийдвэр гарвал өгөгдөл нь бэлэн.

### Цэвэрлэгээ

| Юу | Хэдий хугацаанд |
| --- | --- |
| Баталгаажсан хүргэлт | 180 хоног |
| Ирсэн дугтуй | 180 хоног |
| Хугацаа дууссан урилга | Цаг тутам кодыг нь цэвэрлэнэ (мөр үлдэнэ) |

Ирсэн дугтуйн хадгалалт нь `urtuu.MaxAge`-аас (7 хоног) хамаагүй урт байх ёстой:
хоёулаа хамтдаа replay-ээс хамгаална — дугтуй 7 хоногийн турш л хүчинтэй,
"аль хэдийн ирсэн" гэдгийг хэлэх мөр нь түүнээс хамаагүй удаан амьдарна.

## 10. Хоёр суулгацыг нэг машин дээр турших

SSO federation-ий баримтад бичигдсэн localhost хосын загвар:

```bash
export URTUU_ALLOW_INSECURE_PEERS=1
export URTUU_SIGNING_KEY=$(openssl rand -base64 32)   # суулгац тус бүрд ӨӨР
```

Integration тестүүд яг үүнийг нэг процесс дотор хийдэг:

```bash
URTUU_TEST_DATABASE_URL=postgres://... go test ./modules/urtuu/... ./domain/urtuu/...
```

Гурван давхарга гурвуулаа энэ репогийн CI-д ажиллана. Ролийн нэр, RLS-тэй
холбоотой миграц засвар хийвэл **хаягдах `postgres:16-alpine` контейнер** дээр
шалга: хөгжүүлэгчийн кластерт `gerege_nexus_app`, `gerege_nexus_tenant`
хоёулаа байдаг тул нэрлэсэн бодлого тэнд ажиллаад цэвэр өгөгдлийн сан дээр
унана.
